Worktree Zero · copy-on-write worktrees for agent swarms

Every agent gets a worktree. The disk barely notices.

One command gives a coding agent its own disposable Git workspace — for the disk cost of what it changes, with ports that never collide and cleanup that cannot destroy work.

Agent swarms multiply everything about a checkout except the history.

Git worktrees share commits and blobs, but every worktree materializes the full working tree again — and rebuilds everything Git ignores. Three failures follow. Worktree Zero answers each one.

Problem · duplication

Forty copies of the same files

node_modules, .next, build caches, tracked assets — every worktree pays the full price again, gigabytes per agent.

Answer

Classify, then share. Unchanged tracked files are copy-on-write clones of one canonical baseline (APFS, Btrfs/XFS, ReFS). Dependencies reuse the package manager's own store; only the verified residue is sealed once and cloned. Mutable build state stays private and owned.

Problem · collision

Everyone wants port 3000

Parallel dev servers, Compose stacks, and a shared writable .next between two live agents corrupt each other.

Answer

Identity by construction. Every runtime gets a slot, a hundred-port window claimed from a machine-global registry (bind-probed, unique across every repo on the machine), a Compose project name, and a UUID — exported to the agent's command and to Tilt.

Problem · abandonment

Nobody dares delete anything

Crashed agents leave worktrees, stale branches, held ports, and gigabytes of generated state with no way to tell what's safe to remove.

Answer

Refusal-first cleanup. Ownership markers, leases, and heartbeats make abandonment evidence. wt0 gc removes only with proof — owned, expired, Git-clean, no live process — and preserves and reports everything else.

One versioned contract. Every agent host.

Cleanup that cannot destroy work.

wt0 gc is a dry run by default and --force does not exist. A worktree is removed only when every condition holds; anything else is preserved and reported with the reason.

  • Worktree Zero owns it, on a preserved branch — never a detached commit
  • Its lease has expired and Git reports no modified or untracked work
  • No process has a working directory or open path inside it
  • Every ignored path is recognized generated state or explicitly reviewed — .env* can never be allowed
  • Checked-in pre-remove hooks ran clean — a failing hook vetoes the deletion
